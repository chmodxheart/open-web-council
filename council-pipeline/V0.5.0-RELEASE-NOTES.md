# Council of LLMs v0.5.0 - Enhanced Evaluation Quality Release

**Release Date**: 2025-12-05
**Version**: 0.5.0
**Type**: Major Feature Release

## 🎉 What's New

### 1. Configurable Prompting Techniques

All prompting techniques are now **toggleable via Valves**, giving you fine-grained control over how models respond, evaluate, and synthesize.

#### Initial Query Techniques (11 new Valves)
- `QUERY_USE_HERMENEUTIC_CIRCLE` (default: True) - Apply parts/whole interplay in responses
- `QUERY_USE_CHAIN_OF_THOUGHT` (default: True) - Request step-by-step reasoning
- `QUERY_USE_VERBALIZED_SAMPLING` (default: True) - Show intermediate thinking process

#### Evaluation Techniques (5 new Valves)
- `EVAL_USE_HERMENEUTIC_CIRCLE` (default: True) - Apply hermeneutic circle in evaluations
- `EVAL_USE_VERBALIZED_SAMPLING` (default: True) - Request detailed reasoning process
- `EVAL_USE_SOCRATIC_QUESTIONING` (default: True) - Probe assumptions, gaps, and weaknesses
- `EVAL_USE_ADVERSARIAL_STANCE` (default: True) - Red team analysis for flaws
- `EVAL_USE_CONSTITUTIONAL_PRINCIPLES` (default: True) - Principle-based score justification

#### Synthesis Techniques (1 new Valve)
- `SYNTH_USE_META_COGNITIVE` (default: True) - Reflect on uncertainty and confidence levels

### 2. Dramatically Improved Evaluation Reasoning

**Before v0.5.0:**
```
REASONING: [2-3 sentences explaining your scores...]
```

**After v0.5.0:**
```
REASONING: [Provide a DETAILED analysis explaining your scores. Include:
  - Specific strengths you observed
  - Specific weaknesses or issues you identified
  - Evidence from the response supporting your scores
  - How you weighted different factors in your evaluation
  - Any important caveats or context
  Be thorough—several paragraphs are expected, not just 2-3 sentences.]
```

Evaluators now:
- **Show their thinking** (verbalized sampling)
- **Probe deeply** with Socratic questions
- **Actively look for flaws** (red team analysis)
- **Justify scores** against explicit quality principles
- **Provide detailed, multi-paragraph reasoning** instead of brief summaries

### 3. All Responses Sent to Synthesis

**Before**: Only top N responses (default 2) sent to synthesizer
**After**: ALL responses sent to synthesizer with their scores

**Why this matters:**
- Synthesizer learns from **success AND failure**
- Understands what approaches **didn't work**
- Can avoid pitfalls identified in lower-rated responses
- Makes more informed decisions with complete context

**Message change:**
- Before: `Synthesizing from top 2 responses...`
- After: `Synthesizing from all 3 responses with their evaluations...`

### 4. De-Anonymized User Output

**During Evaluation Phase:**
- Responses remain **fully anonymous** (blind peer review preserved)
- Models don't know which response is theirs or others'

**In Final User Output:**
- Evaluation summaries show **real model IDs**
- Detailed evaluations reveal **which model's response** was evaluated
- User can see "GPT-5.1 evaluated Claude-Sonnet-4.5's response"

**Example:**
```markdown
### Evaluations for **gpt-5.1**'s Response

*(Anonymous ID during review: response_a1b2c3)*

**Evaluator**: claude-sonnet-4.5

- **Accuracy**: 9.0/10
- **Clarity**: 8.5/10
...
```

### 5. Better Error Messages

**Before:**
```
❌ Error: Only 2 models responded successfully. Need 3.
```

**After:**
```
❌ Error: Only 2 models responded successfully. Need 3.

✓ Successful (2): gpt-5.1, claude-sonnet-4.5

✗ Failed (1):
  - groq.moonshotai/kimi-k2-instruct: Connection timeout after 30s
```

Now you can see:
- Which models succeeded
- Which models failed
- WHY they failed (error messages)

## 🔧 Technical Changes

### Dynamic Prompt Building

Three new methods replace static templates:

1. **`_build_initial_query_system_message()`**
   - Dynamically constructs system message based on enabled techniques
   - Adds hermeneutic circle, chain-of-thought, verbalized sampling instructions

2. **`_build_evaluation_prompt(response_text)`**
   - Builds evaluation prompt with selected techniques
   - Requests detailed, multi-paragraph reasoning
   - Includes Socratic questions, adversarial stance, constitutional principles

3. **`_build_synthesis_prompt(question, all_responses, scores, weights)`**
   - Includes ALL responses (not just top N) with their scores
   - Shows ranked list from best to worst
   - Prompts synthesizer to learn from both good and bad approaches

### Prompt Technique Configuration

Templates are no longer static strings in Valves. Instead:
- Removed `EVALUATION_RUBRIC_TEMPLATE` and `SYNTHESIS_TEMPLATE` Valves
- Added 11 boolean Valves to toggle specific techniques
- Prompts built dynamically based on enabled techniques
- More flexible and composable

### Synthesis Changes

## 📈 Impact on Users

### Better Evaluation Quality

Evaluations are now:
- **10-20x more detailed** (paragraphs instead of sentences)
- **More rigorous** (Socratic questioning, adversarial stance)
- **Better justified** (principle-based reasoning)
- **More transparent** (shows evaluator's thought process)

### Improved Synthesis Quality

Synthesizer now:
- Sees **all responses**, not just top 2
- Understands **what didn't work** in lower-rated responses
- Can **avoid identified pitfalls**
- Makes **more informed decisions**

### Transparency & Control

Users can:
- **Toggle any prompting technique** on/off
- See **which model's response** got which scores (de-anonymized)
- Understand **why models failed** (detailed error messages)
- Customize prompting strategies per their needs

### Token Usage

**Increase**:
- Initial queries: ~10-20% more tokens (prompting technique instructions)
- Evaluations: ~50-100% more tokens (detailed reasoning instead of 2-3 sentences)
- Synthesis: ~30-50% more tokens (all responses instead of top 2)

**Overall**: ~40-60% more tokens per Council session

**Trade-off**: Significantly higher quality evaluation and synthesis for moderate token increase

## 📝 Migration from v0.4.0

### Breaking Changes
**None!** All new features are additive with sensible defaults.

### New Defaults
All prompting technique Valves default to `True`, meaning enhanced prompting is enabled by default.

### How to Upgrade

1. **Delete old v0.4.0 function** from Open WebUI
2. **Import new v0.5.0** (`council_orchestrator.json` or `council_llms_complete.json`)
3. **Reconfigure** your `MODELS_TO_QUERY` if needed
4. **Test** with a query - you'll see much more detailed evaluations!

### Customize Prompting Techniques

Want to simplify? Disable techniques via Valves:
```
EVAL_USE_SOCRATIC_QUESTIONING = False
EVAL_USE_ADVERSARIAL_STANCE = False
```

Want even more rigor? Keep all enabled (default).
